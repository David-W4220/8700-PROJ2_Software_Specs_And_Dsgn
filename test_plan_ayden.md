# Test plan: Space Station Inventory and Resupply

Derived only from `spec_ayden.md` (revised Nov 2, 2026) and `architecture_ayden.md`. No implementation code was read. All expected values are computed by hand from the spec.

## Conventions

**Status.** The spec defines no wire protocol, so "status" is the outcome class:

| Status | Meaning |
|---|---|
| Accepted | Saved (station: committed in the onboard store; Earth: committed in the Earth Store) |
| Rejected–validation | Breaks a field or business rule (FR-006–FR-009, FR-017, FR-032…) |
| Rejected–forbidden | The caller's role or `canReopen` does not allow it (FR-003) |
| Rejected–state | Not allowed from the current mission status, or based on a stale version or status (lifecycle, FR-016, FR-031, FR-032) |
| Not found | Unknown ID |
| Acknowledged / Conflict / Rejected (sync) | Earth's outcome for a station update or receipt (FR-029, FR-030) |

**N0 — nothing created.** Every rejection runs N0 plus any case-specific check. N0 means all of the following:

- Station: the item record is unchanged, and no new InventoryUpdate exists (the next station display ID is unchanged).
- Station: the pending count and the alert list are unchanged.
- Earth: the item `recordVersion` is unchanged, and there is no new history entry.
- Earth: there is no new mission ID, mission status, status-history entry or manifest version.
- Earth: there is no new discrepancy, loading issue, conflict or resolution.
- Earth: no new deduplication outcome is stored for the request's `updateId` or `receiptId`.

**Case IDs.** Cases are `AC-nnn.k`. A case marked **extra (X)** was added from the gap checklist and probes requirement X. The Inside/outside and Control columns refer to case IDs.

**One fault per rejection.** Each rejected request differs from its control in exactly one field or condition. The only exception is AC-017.4, a both-limits case the spec itself requires to show that "every failing check is listed". It is marked as such.

**Missions.** R12 is the next mission ID. Its default capacity is 500 kg and 4.0 m3, and its default lines are W01 × 20 and F01 × 40.

- Mass: 20 × 1.0 + 40 × 0.25 = **30.00 kg**
- Volume: 20 × 0.002 + 40 × 0.0015 = 0.04 + 0.06 = **0.10 m3**

**Alerts.** At start, W01 has an Active alert because 6 < 10. F01 and K01 have none.

## Spec gaps

Listed, not resolved.

### A. Requirements with no acceptance criterion

- **A1. NFR-001 to NFR-008.** None of the nonfunctional requirements has an acceptance criterion; AC IDs map only to FRs. They are probed by extra cases here.
- **A2. Unit.** The rule that non-countable units allow up to 3 decimals has no criterion.
- **A3. InventoryItem.** "Barcodes are unique across items" has no criterion.
- **A4. FR-002.** The Earth banner ("Station link"), the 60-second contact window and the definition of "fully completed" have no criterion.
- **A5. FR-010.** Creating items and locations, and editing names, barcodes, criticality, unit mass and unit volume, have no criterion. Only lowering a minimum is tested.
- **A6. FR-012.** "Alerts cannot be raised or resolved by hand" has no criterion.
- **A7. FR-015.** "At most one line per item" (ManifestLine) and `lineQuantity` > 0 have no criterion.
- **A8. FR-016.** Version changes from capacities alone have no criterion.
- **A9. FR-018.** The capacity re-check on approval has no failing criterion.
- **A10. FR-020, FR-021.** The required reason on reopen and on cancel has no failing criterion.
- **A11. FR-022.** Loaded ≥ 0, and loaded above planned, have no criterion.
- **A12. FR-023.** The missing-expected-arrival block and the shortfall warning have no criterion.
- **A13. FR-026.** A note being required on resolution has no criterion.
- **A14. FR-028.** The 7-day limit for Rejected entries has no criterion.
- **A15. FR-029.** Retries with backoff and held-update ordering have no criterion.
- **A16. FR-030.** "Result would be negative", and Usage/Receipt deltas being added, have no criterion.
- **A17. FR-032.** These have no criterion: rejecting a resolution for an update not in conflict, capacities ≤ 0 for volume, rejecting a stale status, ignoring server-set fields beyond `recordedBy`, and escaping all text.

### B. Acceptance criterion content with no requirement

- **B1. AC-006.** The message "Usage saved. New quantity 9 packs. Low stock alert active." is not defined in FR-006, and there is no message for usage that leaves no alert.
- **B2. AC-027.** "Saved locally" is not in FR-027.
- **B3. AC-028.** "Inventory remains available locally" is not in FR-028.
- **B4. AC-007.** The history text format "Store B → Store C" is not in FR-007 or FR-011.
- **B5. AC-001.** The next-mission format "Mission R12 – Approved" is not in FR-001.
- **B6. AC-017.** The exact failure texts are not in FR-017.

### C. Inconsistencies and open points found while computing expected values

- **C1. AC-017 data.** The example totals cannot be built from the default items. 520 kg with only water and food needs at least 1.04 m3, so it cannot have 0.10 m3. 30 kg can reach at most 0.18 m3, so it cannot have 4.20 m3. Test-chosen items P01 and B01 are used instead.
- **C2. AC-030 starting location.** The first scenario says the station moved the repair kit "to Store B", but default data already places K01 at Store B, which AC-007.2 says must be rejected. The test starts K01 at Store A.
- **C3. AC-030 "different fields".** The usage amount and the corrected expiry are not given; the test uses 2 and 2027-03-01.
- **C4. Default data is incomplete.** Location, condition, expiry and barcode for F01, and unit mass, volume, expiry and barcode for K01, are not given. Barcodes and Earth versions are not given for any item. The test-chosen values are marked †.
- **C5. FR-030 additive rule.** "Usage and receipt changes from both sides are added together", but Earth records no Usage or Receipt updates, so the Earth side of this rule has no source.
- **C6. FR-030 negative result.** This is reachable only after a resolution lowers the quantity (AC-030.6), which also hits architecture Spec issue 1.
- **Unstated rules that block cases (referenced as G-B1 to G-B7 in the table):**
